# Codex ↔ DeepSeek Harness 双向桥使用手册（新手版）

这个项目安装好后，你只需要完成下面三步。

> 安装时请在 **Codex 和 DeepSeek Harness 中任选一个**，让它一次安装 `codex-bridge` 和 `deepseek-bridge`。不要让两个代理同时安装，避免它们同时修改同一份配置。

## 第一步：准备项目

1. 确认 Node.js 版本不低于 24：

   ```bash
   node --version
   ```

2. 安装 DeepSeek Harness，并按提示完成登录：

   ```bash
   npm install -g @deepseek-ai/dsh
   dsh --version
   ```

3. 记下这个项目的绝对路径。下面提示词中的 `<LAB_ROOT>` 都要替换成该路径，例如：

   ```text
   /Users/你的用户名/Projects/deepseek-bridge-codex
   ```

项目 clone 下来后不需要执行 `npm install`。

## 第二步：任选一个代理安装两个 bridge

下面两种方式只选一种。安装需要写入 `~/plugins`、`~/.agents` 和 `~/.dsh`；代理申请这些写入权限时，请确认目标路径正确后批准。

### 方式 A：让 Codex 一次安装两个 bridge

把下面整段提示词发给 Codex。发送前先将所有 `<LAB_ROOT>` 替换为项目绝对路径。

```text
请帮我一次安装当前项目中的 codex-bridge 和 deepseek-bridge，建立 Codex 与 DeepSeek Harness 的双向调用。全部由你执行，不要让我手工编辑 marketplace、JSON 或 YAML 文件。

项目根目录：<LAB_ROOT>

开始前先确认以下文件存在；任何一个不存在都立即停止并告诉我，不要猜路径：
- <LAB_ROOT>/plugins/codex-bridge/.codex-plugin/plugin.json
- <LAB_ROOT>/plugins/codex-bridge/.mcp.json
- <LAB_ROOT>/plugins/deepseek-bridge/dsh-web.patch.yml

请依次完成：

1. 检查 node --version 不低于 24，找到 dsh 和 codex 的真实可执行文件路径，并分别运行 --version。优先使用 command -v；macOS 上找不到 codex 时检查 /Applications/ChatGPT.app/Contents/Resources/codex。依赖缺失时停止并明确告诉我。

2. 安装 codex-bridge：
   - 将 <LAB_ROOT>/plugins/codex-bridge 同步到 ~/plugins/codex-bridge；如目标已存在，只替换该插件目录，不得删除 ~/plugins 中的其他内容。
   - 修正 ~/plugins/codex-bridge/.mcp.json：将项目旧绝对路径替换为 <LAB_ROOT>，将 LAB_DEEPSEEK_COMMAND 的值改为真实 dsh 路径，其他字段保持不变。
   - 确保 ~/.agents/plugins/marketplace.json 的 personal marketplace 中包含 codex-bridge 条目，source.path 为 ./plugins/codex-bridge；保留文件中已有的其他插件条目。
   - 执行 codex plugin add codex-bridge@personal。

3. 安装 deepseek-bridge：
   - 执行 dsh --profile web --dump-config >/dev/null 初始化 Web profile。
   - 根据 <LAB_ROOT>/plugins/deepseek-bridge/dsh-web.patch.yml 生成 ~/.dsh/profiles/web/cordis.patch.yml。
   - 只替换模板中的机器相关路径：项目路径改为 <LAB_ROOT>，LAB_CODEX_COMMAND 改为真实 codex 路径，LAB_DEEPSEEK_COMMAND 改为真实 dsh 路径；其余配置保持不变。

4. 静态验证：
   - codex plugin list 必须显示 codex-bridge@personal 为 installed, enabled。
   - dsh --profile web --dump-config 的输出必须包含 mcp-codex-bridge 配置块。
   - 两份配置里不得残留开发者机器上的旧路径；最终路径必须指向 <LAB_ROOT> 和本机真实的 codex、dsh 可执行文件。

全部成功后告诉我“两个 bridge 已安装”，并列出验证结果。任何一步失败都返回失败命令和原始错误，不要静默跳过、不要假装成功。
```

## 最后一步：启动项目并验证

无论选择哪种安装方式，都需要完成下面四项。

1. **启动当前项目**。打开一个新终端，进入项目目录并启动 Bridge：

   ```bash
   cd <LAB_ROOT>
   npm start
   ```

   看到包含 `"event":"labd.started"` 的日志就表示项目已经启动。使用 Bridge 期间请保持这个终端运行，不要关闭。

   如果提示 socket 已被占用，先在另一个终端执行：

   ```bash
   cd <LAB_ROOT>
   npm run labctl -- status
   ```

   如果返回 `"status": "ok"`，说明项目已经被插件自动启动，不需要再运行第二个实例。

2. **重启 DeepSeek Harness Web**：

   ```bash
   dsh web
   ```

   如果旧的 Harness Web 仍在运行，先在其终端按 Ctrl+C，再重新执行 `dsh web`。

3. **新建一个 Codex 任务**。插件只会在新任务启动时加载，安装前已经打开的旧任务不会自动获得 bridge。

4. **验证两个方向**：

   - 在新的 Codex 任务中输入：

     ```text
     请让 DSH 分析这个项目，只返回风险清单
     ```

     应看到 Codex 调用 `deepseek_do_work`，并返回真实 DeepSeek Harness 结果。

   - 在新的 DeepSeek Harness 会话中输入：

     ```text
     请使用 Codex 分析这个项目的架构
     ```

     首个执行动作应为 `mcp__codex_bridge__codex_do_work`，并返回真实 Codex 结果。

两个方向都成功，即表示当前项目已正常启动，`codex-bridge` 和 `deepseek-bridge` 已安装并生效。

## 调高并发数（可选）

Bridge 默认每个目标 agent（Codex、DeepSeek Harness）最多同时执行 **4** 个任务。需要更高并发时，在项目根目录创建 `lab.config.json`（参考 `config/lab.example.json`）：

```jsonc
{
  "maxConcurrentPerAgent": 4
  // 也可以按方向分别设置：
  // "maxConcurrentPerAgent": { "codex": 2, "deepseek": 6 }
}
```

也可以用环境变量：`LAB_MAX_CONCURRENT_PER_AGENT`（两个方向）、`LAB_MAX_CONCURRENT_CODEX`（仅 DeepSeek → Codex）、`LAB_MAX_CONCURRENT_DEEPSEEK`（仅 Codex → DeepSeek）。修改配置后需要重启 Bridge（见下方“不使用时怎么停止服务”）。执行 `npm run labctl -- agents` 可查看每个方向的 `maxConcurrent` 与 `active` 并发数。

## 不使用时怎么停止服务

1. **停止当前项目的 Bridge**：

   - 如果是通过 `npm start` 前台启动的，回到运行它的终端按 Ctrl+C。
   - 如果是插件自动在后台启动的，先确认进程，再停止这个项目对应的进程：

     ```bash
     pgrep -fl "<LAB_ROOT>/apps/labd/src/main.ts"
     pkill -TERM -f "<LAB_ROOT>/apps/labd/src/main.ts"
     ```

     执行前请确认第一条命令显示的路径正是当前项目。`SIGTERM` 会让 `labd` 正常关闭并清理 Unix socket。

2. **停止 DeepSeek Harness Web**：回到运行 `dsh web` 的终端按 Ctrl+C。

如果只是临时禁止 Bridge 接收新任务、但不退出进程，可以执行：

```bash
cd <LAB_ROOT>
npm run labctl -- bridge stop "维护"
```

恢复接收任务：

```bash
cd <LAB_ROOT>
npm run labctl -- bridge resume
```

> `bridge stop` 是暂停开关，会取消当前运行并拒绝新任务，但不会关闭 `labd` 进程。彻底停止服务请使用上面的 Ctrl+C 或 `pkill -TERM`。
